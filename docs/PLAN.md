# PLAN — small-nba

Basesmall 的 NBA 版：一個浮在桌面角落、不打擾工作的比賽在場感小視窗。本文件是動工前的計畫，尚未開始實作。

標記沿用 Basesmall：**【已決定】** 已拍板；**【建議】** 提案；**【待決】** 需要維護者回答；**【未驗證】** 還沒實際打過 API。

## 0. 前提與假設

- 【建議】技術棧沿用 Basesmall：Tauri v2 + TypeScript + Vite + Vitest，Node 24 直接執行 `.ts`。
- 【建議】獨立 repo，不在 Basesmall 裡做「多聯盟抽象」。標準化模型直接設計成籃球的形狀，不去遷就棒球。
- 【建議】Basesmall 是 Apache-2.0、同一位作者，聯盟無關的模組（殼、面板、設定、輪詢節流、重播節奏、tween、音效、i18n 機制）可以搬過來，保留授權標頭與 NOTICE。
- 原則照舊【已決定，沿用 Basesmall】：渲染層不碰原始 JSON、每個功能都是開關、做得更少而不是更像、不做伺服器端或商業化、不用聯盟與球隊的 logo（隊色可以）、不提交任何 NBA 回應。

## 2. 里程碑

每一步都要有能失敗的驗證，沒過不往下走。

### M0 資料探針

- 寫 `scripts/probe/`：今日賽程、單場 play-by-play、boxscore、已結束比賽的完整資料。
- 實測並寫進 `docs/PROBE_REPORT.md`：欄位名稱、時間格式（比賽鐘 vs. 牆鐘）、更新頻率、快取標頭、CORS、回應大小、有沒有增量更新、季後賽與延長賽的樣子。
- 存幾場已結束比賽的夾具到 `fixtures/nba/`（不提交）：一般比賽、延長賽、大逆轉、季後賽。
- **驗證**：夾具的逐球累計比分等於官方 boxscore 的終場比分與各節得分。

### M1 標準化模型與轉換層

- `src/model/types.ts`：`GameState`（節次、比賽鐘、比分、球權、各節得分、團隊犯規、暫停數、場上球員）與 `GameEvent`（得分、投籃不進、失誤、犯規、罰球、換人、暫停、節次結束、比賽結束）。
- `src/data/nba/timeline.ts`：原始資料轉成 `TimelineEntry[]`。
- **驗證**：`tests/timeline.test.ts` 拿夾具對照官方 boxscore（比分、各節得分、球員得分），只對官方數字，不對自己算的數字。

### M2 即時來源與重播

- 搬 Basesmall 的輪詢節流與退避（同時只有一個請求、隱藏時降頻），換成 NBA 端點。
- 搬重播節奏（原速、緊湊、只看結果）。
- **驗證**：假時鐘測試輪詢間隔與退避；拿夾具重播，事件順序與時間正確。

### M3 桌面殼與最小畫面

- 搬 Tauri 殼、面板、設定、i18n（繁中 / 英文）。
- 只做最小的兩種尺寸：「點」（比分、節次）和「條」（再加剩餘時間、球權、得分跑動）。
- **驗證**：拿夾具重播，兩種尺寸都能完整跑完一場；本機打包可以啟動。

### M4 跟隊與通知

- 跟隊邏輯（主隊比賽中、今天稍後有比賽、休息日、淘汰）。
- 緊張度改成：剩餘時間 × 分差 × 季後賽 × 系列賽決勝場。
- 通知規則：開賽、終場、關鍵時刻（例如第四節最後 2 分鐘分差 5 分內）、逆轉。
- **驗證**：用夾具與假時鐘測試跟隊決策與通知觸發條件。

### M5 視情況才做

- 球場視圖（看 Q4 的答案）、隊色風格檔、計分板、自動更新、發佈流程。

## 4. 風險

- 資料源沒有正式授權，隨時可能改格式或擋請求，轉換層要對缺欄位寬容。
- 籃球事件密度比棒球高很多，動畫佇列可能要合併或略過，不能一個一個播。
- 比賽鐘在暫停和罰球時會停，「緊湊」重播要用比賽鐘還是牆鐘【待決，M0 實測後決定】。
